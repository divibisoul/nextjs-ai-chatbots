# SOUL — Unified Engineering Coordination Contract

This repository is N04, an independent AI nucleus cooperating through the single Soul Mesh.

GitHub is source of truth. Preserve and adapt working functionality; audit before and after changes; do not stop structural implementation because runtime commissioning is unavailable; never create a second Mesh. Every nucleus is an independent AI with agents, capabilities, tools, ingress, egress, discovery, delegation and response. Authentication is separate from capability authorization. Maintain the common identity/correlation/timestamp/nonce/HMAC contract. Avoid duplication by adapting existing components. Research viable alternatives when limitations appear.

Engineering pair order: N06↔N05 → N05↔N04 → N04↔N03 → N03↔N02 → N02↔N01. Runtime routing remains Mesh-wide.

Two adjacent connection fronts may be developed simultaneously when their changes are compatible. Findings must be handed forward through GitHub records. A handoff records source, target, connection, commit, changed files, findings, corrections, affected capabilities/agents/tools, dependencies, remaining work, compatibility, next consumer and commissioning status.

## Cumulative master directive

The six nuclei are six independent IAs, not merely six applications. Their agents, capabilities, tools, context and execution resources must be treated as composable computational resources. The Soul Mesh is the canonical interoperability layer and may negotiate hybrid transports such as HTTP, realtime, events, loopback or internal adapters when appropriate; no parallel duplicate Mesh is to be created.

Every audit is both historical and real: inspect the current GitHub state, commits, branches, documentation, architecture, agents, capabilities, tools, providers, ingress, egress, discovery, delegation, execution, tests, CI, dependencies, security and performance. Classify findings and turn every actionable divergence into correction, completion, integration or optimization rather than merely reporting it.

## Failure-antibody rule

Every discovered defect, omission, inconsistency, fragile path, disconnected component, mock, unregistered capability, absent implementation, unused implementation or incomplete contract is an active engineering task. The default reaction is:

DETECT → DIAGNOSE → RESEARCH ALTERNATIVES → CORRECT → COMPLETE → CONNECT → OPTIMIZE → VALIDATE → DOCUMENT → RE-AUDIT.

Do not stop because the first solution fails. Try the next technically appropriate alternative and continue until the defect is resolved, a real technical blocker is demonstrated, or the change is proven inappropriate. Never mask an error or declare success without evidence.

## Simultaneous-front coordination

Assume six independent engineering conversations may be changing the six repositories concurrently. Never infer that work was not done because it is absent from the current conversation. GitHub is the shared memory. Each front must inspect the current repository before mutation and leave durable coordination artifacts containing WHAT_CHANGED, WHAT_WAS_FOUND, WHAT_REMAINS and WHAT_NEXT_AGENT_SHOULD_DO, including commit/branch, dependencies and blockers.

Pair work may proceed concurrently with nucleus work. Pair completion must cross-check agents × tools × capabilities × context × execution and identify technically justified emergent capabilities. Higher-order fusion is capability composition, not repository merging.

## Closure invariant

A nucleus is not closed merely because code exists or documentation says it is complete. Structural closure requires independently deployable AI identity, agents, tools, capabilities, ingress/egress, Mesh interoperability, discovery, delegation, correlation, authorization, resilience, observability, CI evidence and documented remaining live-commissioning work. Runtime commissioning can remain pending when the other nuclei are unavailable, but structural implementation must continue.

Completion means structurally compatible AI role, agents, tools, capabilities, Mesh ingress/egress, discovery, delegation, correlation, authorization and failure handling. Optimize pair combinations for multiplicative capability, reuse, parallelism, low latency, resilience, least privilege and minimal duplication.
